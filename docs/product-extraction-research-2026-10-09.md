# Product extraction options — 2026-10-09

Goal: extract requested shopping products from conversational Ukrainian and English, then assign each item to the existing 15 aisles. Prefer local inference on the VPS that already runs Whisper, little integration work, and no recurring API charge. This is source research, not a tested implementation.

## Recommendation

Pilot a multilingual GLiNER checkpoint before building custom NLP. Start with `urchade/gliner_multi-v2.1` for straightforward span extraction; also consider the current GLiNER2 multilingual checkpoint if one library for extraction and classification is preferable. **Neither source establishes reliable Ukrainian grocery extraction**, so a small evaluation is the next decision gate. This recommendation is an engineering judgment based on the available interfaces, not a measured quality comparison.

Use one broad extraction label such as “shopping product” or “food or household shopping item”; assign each extracted product to an aisle afterwards. Compare direct extraction using 15 aisle labels as a second variant. Keeping these steps separate makes omissions and category mistakes easier to diagnose. Preserve modifiers such as “безлактозне”, “заморожений”, and “дитячий”: aisle decisions can depend on them. Generic NER detects mentions; it does not establish that a mention is a purchase request, so test negation and corrections explicitly.

## Small evaluation before choosing

Prepare about 30 manually annotated messages: 12 Ukrainian, 8 English, 5 mixed-language, and 5 difficult conversational/Whisper-style cases. Spread expected items across all 15 aisles and include multiword products, inflected Ukrainian names, quantities, brands, household goods, repeated items, negation, and self-correction. Example: “Купи молока, ні, краще безлактозного, і два огірки; хліб не треба.” Expected purchase items should reflect the correction and exclude bread.

Score extraction precision/recall, aisle accuracy on correctly extracted items, exact complete-message success, and false additions after negation. Keep canonical item names and quantities separate from span matching. Set acceptable error rates before tuning. A 30-message set is a smoke test, not a production benchmark; reserve fresh messages for a second check after choosing labels/prompts.

Measure actual peak process memory, warmed request latency, and contention while Whisper runs on the target VPS. Download size and parameter count are not total runtime memory. No hardware fit, throughput, grocery accuracy, or recurring VPS cost is claimed here. Serializing Whisper and extraction may be sufficient for low traffic, but that needs measurement.

If multilingual GLiNER passes, use it and a small cached map of confirmed product-to-aisle decisions. If extraction succeeds but classification fails, adjust aisle descriptions or add a separate classifier. If negation/corrections fail, compare a small Qwen3 model on the same set. Avoid fine-tuning or a large dictionary until the evaluation identifies a specific gap.
